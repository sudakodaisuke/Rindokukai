# 輪読ノート

元のStreamlitアプリの機能を引き継ぐ、Next.js App Router版。元の `app.py` はそのまま残しています。

## 開発

```sh
cd web
npm ci
npm run dev
```

`npm run build` で本番ビルド、`npm test` で文分割・出力・翻訳応答の検証、`npm run typecheck` で型検査。

## Vercel

リポジトリをインポートし、Root Directoryを `web` に設定。Next.jsとして自動検出できます。環境変数やDBは不要です。APIキーは各ユーザーが「翻訳の設定」で入力します。既存のStreamlitアプリの起動には影響しません。

## 機能とデータ

- PDFを端末内で読み込み、ページ範囲を指定して本文抽出・プレビュー。英文の直接入力にも対応。
- Geminiの英語語順訳、DeepLの自然な訳、DeepL→Geminiの語順整理。
- 6文ずつ処理、進捗・停止・失敗部分の再実行。英文の保持と対訳の文節数を検証。
- Geminiで表示ページの図・数式・表を読み取り。
- 訳文編集・文ごとのメモ・確認マーク、台本コピー・テキスト書き出し・印刷からPDF保存。
- 下書きの自動保存、名前付きノート保存、JSONでの端末間移動。
- サンプルは用意した固定の対訳。APIキーなしで閲覧・編集を試せます。

PDF本体はブラウザ内で処理。翻訳時に本文、図表読取時に表示ページの画像を、ユーザーが指定した翻訳APIへサーバー経由で送ります。APIキーはReactのメモリ内のみ保持し、LocalStorage・保存ノートには入れません。画面の再読み込みで消去されます。台本・下書きはこのブラウザのLocalStorageに保存するため、共有端末では保存内容に注意し、必要に応じてブラウザのサイトデータを消去してください。

元のハンドブックはGitHub LFSの公開URLからブラウザに直接読み込みます（約92MB）。自動読込に失敗する環境では、PDFをダウンロードして手動アップロードしてください。画像だけのPDFはOCR済みのPDFを用意してください。AIの翻訳と図表解釈は、必ず原文と照らし合わせて確認してください。

初回API実翻訳はユーザーのキーで検証が必要。自動テストはプロバイダの応答を模擬し、外部APIに課金しません。
